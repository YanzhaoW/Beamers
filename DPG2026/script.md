1. Hello everyone. Welcome to my talk about using millepede algorithm in NeuLAND calibration.

2. But before I go deep into the millepede and calibration, I want to shortly talk about NeuLAND. NeuLAND is the neutron detector in R3B at Fair project. Currently, it has 26 scintillation planes. For every two planes, the first plane is composed of 50 scintillation bars, placed horizontally and the second plane is composed of the same amount of bars, but placed vertically. Each bar has two PMTs attached in both ends. Thus, we have 1300 PMTs and 2600 bars in total for this single neutron detector. With this large amount of PMTs and bars, NeuLAND is designed to accurately measure the time and position values of all interactions from changed particles travelling inside the detector. But to calculate these values, we need some parameters when are obtained during the calibration.

3. So the NeuLAND calibration is done by using the data from cosmic muons. For each bar, we have 3 parameters that we use to calculate the time and positions values. Since we are also using muon tracks, the whole calibration equation also contains addition parameters to account for the different orientation and offset of the track. As we have 1300 scintillation bars, we have 3900 parameters plus a bunch of other parameters relating to the muon track. The current method simplifies this equation by reconstructing muon tracks with active bar positions. From the side view and the top view of the detector, we could see that the active bar positions could give us a good estimation about the orientation and the offset of muon tracks. Once the track is determined, we only need to calculate the remain 3900 parameters during the data fitting. But unfortunately, this method is not very accurate as it's using the bar position data which has an uncertainty of 5cm. So to have a more accurate calibration, we have to, in some way, go back the data fitting of all parameters.

4. We all know that the process of data fitting is no other than the minimization of so-called objective function. And we also know that there are generally two popular methods for the minimization: one is the gradient decent and the other is newton's method. And the for the data fitting, newton's method is usually the go-to method. But newton's method has two problems: first the hessian matrix sometimes could be expensive to calculate and this is solved Quasi newton's method like BFGS. But what it still cannot solve is the heavy computation when we have a very large number of parameters, which leads to a very large dimension of matrix. In our case, this is very unacceptable as the dimension of matrix is now proportional to the number of muon tracks we use, but we want to use as many muon tracks as available.

5. Fortunately, special problems always have special solutions. What is special in our case is that only 3900 parameters from the bars are needed for the calculation of time and position values. Parameters related to one muon track are independent to another. The millepede algorithm that I'm going to show you next is exactly based on these two special conditions. So what the millepede algorithm does is to divide all parameters into global parameters and local parameters. Through some magic, we can the original iteration of in the Newton's method, where all parameters get updated, to the iteration where only the global parameters get updated. And we can also see that the dimension of the matrices in the iteration equation is now only equal to the number of global parameters. Thus, by using the millepede algorithm, we are fitting the parameters like fitting all parameters simultaneously. And now the computation complexity is independent of the number of muon tracks, and we can use as many of them as possible.

6. The millepede algorithm is implemented in a program called Millepede-II, which has two parts: Mille and Pede. The mille part takes the user input and save it to the binary file, which is then used by the pede to generate the results of the fitted parameters. But it has three prerequisites. First, the calibration equation must be linear. In case of non-linear equation, we also need good initial values such that we could do Taylor expansion around these good initial values to change into linear equation. And finally, there has to be no rank deficit. For now, I want to talk a bit more about rank deficit as it's the biggest problem for me while using millepede algorithm. So the rank deficit sometimes can be reported by the program, but sometimes not. To understand it, we could use a very simple equation with three parameters a, b and c. It's not hard to see that no matter how many data points are available, these three parameters are basically unsolvable as the matrix that we need to inverse has a rank deficit. To fix this, the most easy way is just to fix one the parameters that cause the rank deficit. In this case, we need to either fix b or c. For the same principle, during the adaptation of the millepede algorithm to NeuLAND, we have to first assume the all muons are travelling at the speed of the light inside the detector and one scintillation bar has the time synchronization parameter fixed to be 0. After the rank deficit is gone, the program can be about to produce the valid results.

7. So what do results look like? Here are the two plots to show the improvement of the millepede over the initial values for two parameters. In the first plot, we can see there are some unnatural increases of the parameter values for the bars located at the edge of scintillation plane. But from the results of Millepede algorithm, these increases are evened out. The second picture shows that if the parameter values are already accurate, the millepede algorithm doesn't make them worse. But how do we know which parameters are more accurate, or closer to the true values? What we can do in such validation process is to use these parameter values to calculate the positions of the muon interactions inside the detector, fit a line through those positions and calculate the residual values of each data point. If the parameters are accurate, we can say the residual values must be centered around the zero value. And this is exactly what we see from the results of the Millepede algoirthm, but not from the initial values. Thus, we can safely say that the millepede algorithm does make a significant improvement on the initial parameter values.

8. To compare the current method and the millepede algorithm, we can use exactly the same validation process to see which one generates more accurate results. But in this case, I want to show the residual distribution for all bars in a 2-dimensional histogram. If you look closely, you may see the results from the millepede algorithm are more centered around zero values compared to the results from the current method, especially in this region. If you don't see the difference, in the third plot, I compute the mean values of the residual distribution for the millepede algorithm and the current method. Here we can clearly see that the results of the millepede are better centered around the zero values, and thus less biased.

9. So let me wrap it up. So in this talk, we have seen how the millepede algorithm greatly reduces the computation complexity and improve the accuaracy of the parameter values. We also saw that the results that we get by using millepede are less biased than the results from the current method. For the outlook, we are actively developing a program called centipede, which is a reimplementation of the millepede but in C++26. And apart from this, we also plan to apply the same algorithm to the energy related parameters as well. So that's the end of my talk. Thanks for listening.
